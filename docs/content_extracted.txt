1. KẾT LUẬN TRIỂN KHAI VÀ PHẠM VI
1.1. Mục tiêu code
Xây dựng nền tảng số có thể tiếp nhận, xác minh, điều phối và theo dõi sự kiện theo vị trí; đồng thời quản trị lớp dữ liệu giao thông và tích hợp VietMap qua một Adapter tập trung. Hệ thống phải phục vụ năm nhóm: công dân/du khách, trực ban, đơn vị địa bàn, lãnh đạo và quản trị hệ thống.
Luồng cốt lõi 1: SOS tai nạn/CNCH từ công dân đến trung tâm chỉ huy, gợi ý đơn vị theo vùng phục vụ và ETA, theo dõi các mốc tiếp nhận - di chuyển - hiện trường - hoàn tất.
Luồng cốt lõi 2: phản ánh vi phạm kèm tọa độ và bằng chứng, chống spam/trùng, che định danh, xác minh trước khi dùng nghiệp vụ, cấp mã tra cứu tổng quát.
Luồng cốt lõi 3: quản trị và công bố đường cấm/hạn chế, điểm nguy hiểm, bãi đỗ, cấm dừng/đỗ và sự kiện tạm thời có thời hạn hiệu lực.
Luồng nền: phân quyền, audit, thông báo, dữ liệu không gian, VietMap, quan sát hệ thống, sao lưu/phục hồi và vận hành theo SLA.

3.2. Kiến trúc ứng dụng
Modular monolith: một API deployable nhưng module không import trực tiếp repository của nhau; giao tiếp qua application service, domain event hoặc contract công khai.
CQRS mức vừa đủ: command cho thay đổi trạng thái; query model tối ưu cho hàng đợi/dashboard. Không áp dụng event sourcing toàn hệ thống.
Transactional Outbox: mọi thay đổi cần phát sự kiện ghi cùng transaction; relay đẩy sang RabbitMQ; consumer idempotent.
Provider ports/adapters: VietMap, object storage, notification, antivirus, identity là interface; test bằng fake adapter; không rải SDK vendor trong domain.
Deny-by-default: controller chỉ gọi use case sau authentication/authorization; repository luôn nhận access scope đã tính.
No silent degradation: khi dùng ETA fallback hoặc dữ liệu cache cũ, response và UI phải có quality flag/observed_at.

4.2. Quy tắc phụ thuộc module
Controller -> application use case -> domain -> port -> infrastructure adapter. Domain không import NestJS, ORM, HTTP SDK hoặc biến môi trường.
Module khác chỉ gọi public application service hoặc consume event; cấm import sâu đường dẫn internal.
DTO API không được dùng làm entity database. Mapping rõ ràng tại boundary.
Mọi timestamp là UTC trong backend/database; UI hiển thị Asia/Ho_Chi_Minh; tên trường dùng *_at.
Mọi ID nội bộ dùng UUID/ULID; mã tra cứu public sinh riêng, không tuần tự, không suy đoán được.
Tiền/chi phí/quota không dùng float. Tọa độ validate range; GeoJSON tuân thủ [longitude, latitude].
Error response theo RFC 7807 Problem Details; có error_code ổn định, trace_id và thông điệp không lộ nội bộ.

6.2. Quy ước dữ liệu không gian
API trao đổi GeoJSON EPSG:4326; thứ tự tọa độ bắt buộc longitude, latitude.
Điểm dùng geography(Point,4326) khi đo mét; đoạn/vùng dùng geometry với GiST index và quy tắc validity.
Lưu original_coordinate, normalized_coordinate, accuracy_m, source_crs và normalization_method khi có chuyển đổi.
Mọi đối tượng thời hạn có valid_from, valid_to và publication_state; public query luôn lọc thời gian hiệu lực.
Không trả dữ liệu hình học nội bộ của lực lượng/địa bàn nhạy cảm qua public API.
6.3. State machine SOS/incident
RECEIVED -> AUTO_SCREENING -> PENDING_VERIFICATION -> VERIFIED
VERIFIED -> ASSIGNED -> ACKNOWLEDGED -> EN_ROUTE -> ON_SCENE -> RESOLVED -> CLOSED
PENDING_VERIFICATION -> REJECTED | DUPLICATE
ASSIGNED -> ESCALATED | REASSIGNED
Any active state -> CANCELLED only with reason + authority
Mỗi transition có precondition, actor role, required fields, timestamp và audit event.
ASSIGNED tạo SLA deadline; ACKNOWLEDGED hủy timer; quá hạn phát assignment.ack_timed_out và escalation.
Không cho nhảy thẳng RECEIVED -> CLOSED; sửa lịch sử bằng event bù, không update/xóa history.
Citizen chỉ thấy trạng thái tổng quát: đã tiếp nhận, đang xử lý, đã hoàn tất/không đủ cơ sở.
6.4. State machine phản ánh và lớp dữ liệu
REPORT: RECEIVED -> SCREENING -> PENDING_VERIFICATION -> VERIFIED | REJECTED | DUPLICATE
        VERIFIED -> IN_PROCESS -> RESOLVED -> CLOSED -> ARCHIVED
MAP VERSION: DRAFT -> IN_REVIEW -> APPROVED -> PUBLISHED -> EXPIRED | WITHDRAWN -> ARCHIVED
Invariant: Tin người dân và OCR chỉ là đầu vào chưa xác minh. Không có code path nào biến REPORT thành quyết định xử phạt; kết quả nghiệp vụ phải do actor có thẩm quyền và được audit.

7.4. Dispatch ranking

8. THIẾT KẾ TÍCH HỢP VIETMAP
8.1. Nguyên tắc adapter
Theo tài liệu VietMap hiện hành, service API nên được gọi từ backend; VietMap có SDK Web GL, Flutter và React Native. Kế hoạch dùng React Native SDK cho hiển thị bản đồ mobile và backend Adapter cho search/geocode/reverse/routing/matrix. Khóa client và server phải tách loại, hạn chế domain/IP/API/quota theo khả năng Console/hợp đồng.
Domain chỉ biết MapProviderPort; adapter chuẩn hóa request/response về model nội bộ.
Không gửi incident_id, public_code, danh tính, bằng chứng, ghi chú hoặc vị trí lực lượng cho provider; chỉ gửi tọa độ/tùy chọn route cần thiết.
Cache key bỏ dữ liệu nhạy cảm, làm tròn tọa độ theo use case; TTL riêng search/reverse/route/matrix; không cache sai điều khoản giấy phép.
Timeout, retry có jitter, circuit breaker, bulkhead và quota budget cho từng API/environment.
Mọi response có provider, api_version, observed_at, cache_status, quality và latency_ms để truy vết.
Không để key trong mobile bundle trừ key SDK bắt buộc đã giới hạn; server key chỉ ở secret store.
8.2. Interface nội bộ
interface MapProviderPort {
  search(input: SearchInput, ctx: ProviderContext): Promise<SearchResult[]>;
  reverse(input: ReverseInput, ctx: ProviderContext): Promise<AddressResult>;
  route(input: RouteInput, ctx: ProviderContext): Promise<RouteResult>;
  matrix(input: MatrixInput, ctx: ProviderContext): Promise<MatrixResult>;
}
type ProviderQuality = 'LIVE' | 'CACHED' | 'DEGRADED' | 'UNAVAILABLE';
// ProviderContext chỉ chứa trace/budget/locale, tuyệt đối không chứa PII hay case notes.
8.3. Acceptance tests VietMap
Search/reverse/route/matrix map đúng schema, tọa độ và error code; contract test dùng recorded sanitized fixtures được phép.
Key không xuất hiện trong log, error, source map, bundle public hoặc snapshot test.
Circuit mở sau ngưỡng; request mới fail-fast; nhận SOS vẫn 201/202 và outbox vẫn phát.
Quota 70/85/95% phát cảnh báo khác mức; dashboard tách theo key_alias/API/environment.
Cache không trả dữ liệu quá max-stale; response gắn observed_at/quality; UI hiển thị suy giảm.
Không gọi provider trong transaction database và không retry vô hạn.

10.2. Evidence pipeline
Initiate: server cấp upload_id, object key ngẫu nhiên, size/MIME allowlist, short-lived upload authorization.
Quarantine: object không đọc được bởi ứng dụng nghiệp vụ; worker xác minh magic bytes, hash SHA-256 và quét mã độc.
Sanitize: loại EXIF không cần thiết khỏi derivative; original được giữ theo policy và mã hóa riêng.
Derive: thumbnail/preview có watermark nội bộ gồm case code + timestamp; không watermark làm thay đổi original.
Finalize: transaction cập nhật READY, lưu checksum/scan engine/version; phát evidence.ready.v1.
Access: preview/download qua authorization service; URL ký thời gian ngắn; mọi hành động ghi audit.
Retention: legal hold chặn xóa; job archive/delete chỉ chạy khi policy đã phê duyệt và tạo audit/báo cáo.
10.3. Privacy vault và break-glass
Thiết kế bắt buộc: Bảng nghiệp vụ report/incident không chứa IP, device identifier hoặc tài khoản có thể nhận diện. Liên kết định danh kỹ thuật tối thiểu, nếu được phép thu, nằm trong privacy vault với DB role và encryption key riêng.
Unmask request cần case_id, căn cứ/văn bản, mục đích, phạm vi trường, thời hạn và người yêu cầu.
Hai approver khác người yêu cầu; kiểm tra separation of duties; MFA step-up.
Grant ngắn hạn, one-time hoặc time-boxed; mọi query trả đúng trường được duyệt; không export hàng loạt.
Thông báo cho đầu mối ATTT/privacy theo rule; audit không thể bị actor nghiệp vụ chỉnh sửa.
Tự động revoke khi hết hạn; báo cáo định kỳ các yêu cầu approved/rejected/used/unused.

16. CÁCH GIAO VIỆC CHO CODEX
16.1. Nhịp làm việc
Mỗi chat/nhánh chỉ có một outcome: ví dụ 'T07 SOS vertical slice', không giao cả sprint.
Bắt đầu ở Plan mode: Codex đọc AGENTS.md, docs/ADR và task plan; liệt kê giả định/câu hỏi blocker.
Nếu thiếu quyết định ở Decision register, Codex tạo interface/feature flag/fake adapter và dừng trước production behavior.
Codex triển khai theo lát dọc nhỏ: migration -> domain -> application -> API -> client -> tests -> docs/observability.
Trước kết thúc, Codex chạy gate, review diff, xác nhận rollback và ghi phần chưa kiểm chứng.
Không dùng một chat cho toàn dự án; sau mỗi task cập nhật plan/status và tạo checkpoint Git có chủ đích.
16.2. Prompt chuẩn cho từng task
MỤC TIÊU
Triển khai [Txx - tên task] theo docs/plans/Txx.md.
NGỮ CẢNH
- Đọc AGENTS.md, PLANS.md và các ADR/module docs liên quan.
- Tài liệu nghiệp vụ nguồn: docs/requirements/ATGT-Lam-Dong.md.
- Chỉ sửa các thư mục được liệt kê trong task, trừ khi cần cập nhật contract/test/docs.
RÀNG BUỘC
- Không suy đoán SLA, retention, quyền gỡ ẩn danh, quota hoặc dữ liệu thật.
- Không làm yếu security/authorization để test pass.
- Không để VietMap/notification nằm trên critical transaction path của SOS.
- Mọi consumer và POST retry phải idempotent; mọi sensitive access phải audit.
CÁCH LÀM
1. Khảo sát repo và tóm tắt current state.
2. Cập nhật execution plan với file cụ thể, migration, test và rollback.
3. Implement theo lát dọc nhỏ; giữ diff trong scope.
4. Chạy format/lint/typecheck/unit/integration/contract/E2E phù hợp.
5. Tự review diff về correctness, security, privacy, HA và regression.
HOÀN THÀNH KHI
- Acceptance criteria của Txx pass.
- OpenAPI/event schema/migration/runbook/observability được cập nhật.
- Báo cáo file đã đổi, test đã chạy, rủi ro/giả định và bước tiếp theo.
16.3. Prompt review bảo mật
Review diff hiện tại như reviewer ATTT cấp cao cho hệ thống tiếp nhận SOS.
Ưu tiên P0/P1: bypass authorization/area/case scope; PII/secret/log leak;
IDOR; upload/malware/path traversal; idempotency/replay; state transition;
queue message loss; provider outage on SOS path; audit gaps; unsafe migration;
fail-open behavior. Chỉ nêu lỗi có đường tái hiện cụ thể, file/vị trí, tác động

PHỤ LỤC A. MẪU AGENTS.MD SẴN DÙNG
# AGENTS.md
## Mission
Build the Lam Dong road-safety map platform. Preserve emergency intake,
privacy, evidence integrity, authorization, auditability and degraded-mode
behavior above feature convenience.
## Repository map
- apps/api: NestJS modular monolith HTTP/realtime API
- apps/worker: outbox/media/notification/SLA/expiry jobs
- apps/citizen-mobile: React Native citizen app
- apps/citizen-web: public Next.js web/PWA
- apps/ops-web: operations, data admin and leader dashboards
- packages/contracts: OpenAPI DTOs, generated clients, event schemas
- packages/domain: framework-free value objects and shared invariants
- infra: local and 09-VPS deployment automation
- docs: ADRs, plans, security, data, UAT and runbooks
## Required workflow
1. Read the closest instructions, relevant ADRs and the task execution plan.
2. Inspect before editing. State blockers; never invent policy values.
3. Keep one coherent outcome per branch/chat and avoid unrelated refactors.
4. Implement migration/domain/application/API/client/test/docs/telemetry as needed.
5. Run the relevant gates and review the final diff before handoff.
## Commands
- pnpm format:check
- pnpm lint
- pnpm typecheck
- pnpm test
- pnpm test:integration
- pnpm test:contract
- pnpm test:e2e
- pnpm build
## Architecture rules
- Default to a modular monolith. Do not add a deployable service without ADR.
- Domain code must not import framework, ORM, HTTP SDK or environment config.
- Cross-module access uses public application services or versioned events.
- Database changes are forward-only and rolling-deploy compatible.
- External providers are ports/adapters; do not call them inside DB transactions.
- Accepted SOS intake must work when VietMap and notification providers fail.
- Use transactional outbox; consumers and retried POSTs must be idempotent.
## Security and privacy rules
- Deny by default; enforce role + unit + area + case + data-class scope in API.
- UI hiding is never authorization.
- Never log tokens, keys, signed URLs, identity data, evidence or case notes.
- Business report/incident tables must not contain citizen technical identity.
- Unmasking requires approved break-glass policy, step-up MFA and immutable audit.
- Files enter quarantine, are type/size/hash/AV checked, then become readable.
- Never make original evidence public or overwrite its checksum/history.
- Never use an unverified citizen report/OCR result as an enforcement decision.
## Geospatial and API rules
- API coordinates are EPSG:4326 GeoJSON [longitude, latitude].
- Public queries return only approved, published and currently valid features.
- Errors use stable Problem Details codes and include trace_id without internals.
- Public tracking codes are random and non-enumerable.
## Testing and done
- Add tests for state transitions, authorization denials, retries and outages.
- Use a fake clock/provider; tests must be deterministic.
- No Critical/High security finding may be hidden or weakened to pass CI.
- Update OpenAPI/event schema, migration, ADR/runbook and observability together.
- Handoff lists changed files, commands/results, assumptions, risks and rollback.
